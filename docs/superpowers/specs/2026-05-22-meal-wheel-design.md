# 今天吃什么轮盘功能设计

> 日期：2026-05-22 | 状态：已确认，待实现

## 概述

新增一个独立功能入口“今天吃什么”，用于通过美食轮盘抽取午饭或晚饭。功能以当前项目的插件式结构接入：首页展示入口卡片，点击后进入独立页面。视觉风格采用暖色、美食卡通、轻松有食欲的方向，同时保留抽奖轮盘的旋转仪式感。

首版目标是解决日常选择困难：打开即可抽，也能逐步维护自己的餐食列表。

## 功能范围

包含：

- 默认餐食池：首次打开功能时自动提供一批常见餐食。
- 自定义餐食：支持添加、删除餐食。
- 午饭/晚饭适用标记：每个餐食可适用于午饭、晚饭，或两者都适用。
- 简单偏好权重：每个餐食可设为“普通”或“更想吃”，“更想吃”抽中概率略高。
- 今天不吃：抽中后可将该餐食临时排除，当天后续不再抽到。
- 仪式感结果：轮盘停止后弹出结果卡片，提供“就吃这个 / 再抽一次 / 今天不吃”。

不包含：

- 历史统计
- 云同步
- 复杂分类
- 精确权重数字
- 多人投票

## 页面结构与交互

### 主页面

页面采用单页主体验，管理操作通过底部面板或对话框完成。

从上到下：

1. 顶部栏
   - 返回按钮
   - 标题：今天吃什么
   - 右侧入口：管理餐食
2. 用餐场景切换
   - 胶囊按钮：午饭 / 晚饭
   - 切换后，轮盘只使用适用于当前场景且未被“今天不吃”排除的餐食
3. 轮盘区域
   - 中央大轮盘
   - 多个暖色彩色扇区
   - 中心按钮：开转
   - 固定指针用于指向最终结果
4. 当前候选摘要
   - 显示当前可选数量
   - 展示若干候选小标签
   - 候选太少时提示去管理餐食
5. 结果弹窗
   - 展示抽中餐食名
   - 展示轻松的推荐语
   - 操作按钮：就吃这个 / 再抽一次 / 今天不吃

### 餐食管理

餐食管理使用底部面板或全屏对话框。列表展示：

- 餐食名称
- 午饭适用开关
- 晚饭适用开关
- 普通 / 更想吃状态
- 删除操作

新增餐食时，名称为空不添加。默认可同时适用于午饭和晚饭，用户可后续调整。

### 空状态

- 当前场景无候选：显示“今天选择太少啦，去加几个好吃的吧”。
- 所有候选都被当天排除：显示“今天的排除项太多啦，可以去管理或明天再抽”。

## 代码结构

新增独立功能包：

```text
app/src/main/java/com/lzm/funchub/features/mealwheel/
├── MealWheelFeature.kt
├── MealWheelScreen.kt
├── MealWheelViewModel.kt
└── data/
    ├── MealOption.kt
    └── MealWheelRepository.kt
```

### MealWheelFeature

实现 `FeatureEntry`，负责：

- 首页显示名称
- 首页图标
- 路由 id
- 提供入口 Composable

在 `CCApplication.onCreate()` 中注册：

```kotlin
FeatureRegistry.register(MealWheelFeature)
```

### MealOption

表示一个餐食候选项，字段：

```kotlin
data class MealOption(
    val id: Long,
    val name: String,
    val forLunch: Boolean,
    val forDinner: Boolean,
    val isFavorite: Boolean,
    val excludedDate: String?
)
```

`excludedDate` 使用本地日期字符串，例如 `2026-05-22`，用于判断“今天不吃”是否仍然生效。

### MealWheelRepository

负责本地数据管理：

- 首次初始化默认餐食
- 从 `meal_options.json` 读取餐食列表
- 写入 `meal_options.json`
- 添加餐食
- 删除餐食
- 切换午饭/晚饭适用标记
- 切换“更想吃”状态
- 设置“今天不吃”

本地存储沿用当前 Todo 功能的轻量 JSON 文件做法。该功能数据量小，使用 JSON 能减少首版复杂度；后续如果项目统一迁移数据库，再一起迁移到 Room。

### MealWheelViewModel

负责页面状态和抽取逻辑：

- 当前用餐场景：午饭 / 晚饭
- 当前可抽候选列表
- 当前是否正在旋转
- 最近一次抽中结果
- 添加、删除、更新餐食
- 执行抽取
- 将结果标记为今天不吃

### MealWheelScreen

负责 Compose UI：

- 渲染顶部栏
- 渲染午饭/晚饭切换
- 渲染轮盘
- 渲染候选摘要
- 渲染结果弹窗
- 渲染餐食管理面板

用户操作通过 ViewModel 修改状态，不在 UI 层直接读写文件。

## 数据流

```text
MealWheelScreen
  -> 调用 MealWheelViewModel
  -> 调用 MealWheelRepository
  -> 读写 meal_options.json
  -> StateFlow 推动 UI 刷新
```

对于 Java/Spring 背景，可以类比为：

- `Screen`：View + Controller 入口
- `ViewModel`：持有页面状态的 Controller/Service
- `Repository`：DAO/Repository
- JSON 文件：轻量本地数据库

## 随机规则

抽取步骤：

1. 按当前场景过滤：
   - 午饭：`forLunch == true`
   - 晚饭：`forDinner == true`
2. 排除 `excludedDate == 今天` 的餐食。
3. 构造加权列表：
   - 普通餐食加入 1 次
   - 更想吃餐食加入 2 次
4. 从加权列表中随机选 1 个。

“更想吃”只是提高概率，不保证一定抽中。

## 轮盘动画

首版使用 Compose 内置动画，不引入额外动画库。

流程：

1. 点击“开转”后禁用按钮。
2. ViewModel 先计算抽中项。
3. UI 根据抽中项计算目标角度。
4. 轮盘旋转多圈后缓慢停到目标扇区。
5. 动画结束后显示结果弹窗。

若候选为空，不启动动画，直接显示提示。

## 错误与边界处理

- 餐食名称为空：不添加。
- 当前候选为空：不开转，显示空状态提示。
- 只剩一个候选：允许开转，结果就是该候选。
- JSON 文件不存在：初始化默认餐食。
- JSON 文件损坏：回退默认餐食，保证页面可用。

- `./gradlew :app:testDebugUnitTest`
- `./gradlew :app:assembleDebug`

手动验证：

- 首页出现“今天吃什么”卡片。
- 点击卡片进入轮盘页面。
- 午饭/晚饭切换后候选列表符合标记。
- 点击开转后出现旋转动画。
- 动画结束后弹出结果卡片。
- “再抽一次”可以重新抽取。
- “今天不吃”后，该项当天不再出现在当前场景候选中。
- “就吃这个”关闭结果弹窗并保留当前页面。
- 餐食管理支持新增、删除、切换午饭、切换晚饭、切换更想吃。
